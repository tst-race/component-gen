# Raceboat Transport Plugin Development Guide

Verified reference for implementing, building and testing a raceboat **decomposed transport component**. Everything here is checked against the headers in `raceboat/include/race/decomposed/` and `raceboat/include/race/common/`, and against code that builds and passes its integration scenarios: `plugins/transport-stub` (the template; every snippet below is a trimmed copy of a file there) and (for the real-service patterns) `plugins/skyhook`. Where this file and a header disagree, the header wins — and please fix this file.

Workflow and rules: `AGENTS.md`. Commands and troubleshooting: `INTEGRATION_TEST_GUIDE.md`. Step-by-step adaptation of the template: `plugins/transport-stub/DEVELOPER_GUIDE.md`.

---

## 1. Architecture

A **channel** is a *composition* of three components, each in a shared library loaded by `race-cli`/the app from `/kits/<PluginName>/`:

| Component | Job | Reference |
|---|---|---|
| **Transport** (you write this) | moves already-encoded bytes through the third-party service | `plugins/transport-stub` |
| **Encoding** | turns app bytes into service-appropriate content and back (base64, image, noop…) | `plugins/decomposed-exemplars` (`noop`, `base64`) |
| **User model** | schedules *when* `post`/`fetch` actions happen | `plugins/decomposed-exemplars` (`twoSixFileBasedUserModel`, `rapidUser`) |

Object hierarchy (see also `raceboat/documentation/plugin-channel-link-conn-pkg.png`): Plugin → Channel → **Link** → Connection → Package. A *link* is one communication path (for us: one service-side container plus one address). The transport creates, loads and destroys links and executes the scheduled actions on them.

Components talk only through the SDK object the framework hands them (`ITransportSdk`). The transport **declares** actions (`getTransportProperties`, `getActionParams`); the user model **schedules** them; the framework asks the encoding for content and calls `enqueueContent` then `doAction`.

Timeline of one post: user model emits `{"linkId":"*","type":"post"}` at *t* → framework calls `getActionParams` → encoding encodes → `enqueueContent(params, action, bytes)` → at *t* `doAction(handles, action)` → link uploads → `sdk->onPackageStatusChanged(handle, PACKAGE_SENT)`. A fetch: `doAction` → link lists/downloads new data → `sdk->onReceive(linkId, params, bytes)` → framework decodes.

### 1.1 Channel/link vocabulary that matters for design

- **Creator / loader** (`LinkSide`: `LS_CREATOR`, `LS_LOADER`, `LS_BOTH`): the creator makes the link and its address; the loader loads that address. `channelProperties.currentRole.linkSide` says which side(s) this node may play.
- **`linkDirection`** (manifest): `LD_CREATOR_TO_LOADER` (creator posts, loader fetches — the pattern of both references), `LD_LOADER_TO_CREATOR`, `LD_BIDI`.
- Which API call builds which link: `createLink` = creator, new address generated by you; `createLinkFromAddress` = creator, address supplied (e.g. `--send-address`); `loadLinkAddress` = loader, address supplied; `loadLinkAddresses` = loader with several addresses (unsupported by the references: report `LINK_DESTROYED` and return an error).
- Full property reference: `raceboat/documentation/ChannelAndLinkProperties.md`.

## 2. API signatures (copy these, do not paraphrase)

```cpp
// raceboat/include/race/decomposed/ITransportComponent.h
class ITransportComponent : public IComponentBase {
  virtual TransportProperties getTransportProperties() = 0;
  virtual LinkProperties getLinkProperties(const LinkID &linkId) = 0;
  virtual ComponentStatus createLink(RaceHandle handle, const LinkID &linkId) = 0;
  virtual ComponentStatus loadLinkAddress(RaceHandle handle, const LinkID &linkId, const std::string &linkAddress) = 0;
  virtual ComponentStatus loadLinkAddresses(RaceHandle handle, const LinkID &linkId, const std::vector<std::string> &linkAddress) = 0;
  virtual ComponentStatus createLinkFromAddress(RaceHandle handle, const LinkID &linkId, const std::string &linkAddress) = 0;
  virtual ComponentStatus destroyLink(RaceHandle handle, const LinkID &linkId) = 0;
  virtual std::vector<EncodingParameters> getActionParams(const Action &action) = 0;
  virtual ComponentStatus enqueueContent(const EncodingParameters &params, const Action &action, const std::vector<uint8_t> &content) = 0;
  virtual ComponentStatus dequeueContent(const Action &action) = 0;
  virtual ComponentStatus doAction(const std::vector<RaceHandle> &handles, const Action &action) = 0;
};
// IComponentBase:  ComponentStatus onUserInputReceived(RaceHandle handle, bool answered, const std::string &response)
extern "C" EXPORT ITransportComponent *createTransport(const std::string &name, ITransportSdk *sdk,
                                                        const std::string &roleName, const PluginConfig &pluginConfig);
extern "C" EXPORT void destroyTransport(ITransportComponent *component);
// plus, once per library:  const RaceVersionInfo raceVersion = RACE_VERSION;

// raceboat/include/race/decomposed/ITransportSdk.h (+ IComponentSdkBase.h)
virtual ChannelProperties getChannelProperties() = 0;
virtual ChannelResponse onLinkStatusChanged(RaceHandle handle, const LinkID &linkId, LinkStatus status, const LinkParameters &params) = 0;
virtual ChannelResponse onPackageStatusChanged(RaceHandle handle, PackageStatus status) = 0;
virtual ChannelResponse onEvent(const Event &event) = 0;                       // Event{ JsonString json }
virtual ChannelResponse onReceive(const LinkID &linkId, const EncodingParameters &params, const std::vector<uint8_t> &bytes) = 0;
virtual std::string getActivePersona() = 0;
virtual ChannelResponse requestPluginUserInput(const std::string &key, const std::string &prompt, bool cache) = 0;  // use .handle
virtual ChannelResponse requestCommonUserInput(const std::string &key) = 0;
virtual ChannelResponse updateState(ComponentState state) = 0;
virtual ChannelResponse writeFile(const std::string &path, const std::vector<uint8_t> &data) = 0;   // also appendFile, readFile, listDir, makeDir, removeDir
virtual std::vector<std::uint8_t> readFile(const std::string &path) = 0;
```

Types (`ComponentTypes.h`): `Action{Timestamp timestamp; uint64_t actionId; JsonString json}`; `EncodingParameters{LinkID linkId; EncodingType type; bool encodePackage; JsonString json}` (brace-init in that order); `TransportProperties{unordered_map<string, vector<EncodingType>> supportedActions}`; `ChannelResponse{ComponentManagerStatus status; RaceHandle handle}` (`CM_OK`/`CM_ERROR`); `ComponentStatus` = `COMPONENT_UNDEF|OK|ERROR|FATAL`; `ComponentState` = `COMPONENT_STATE_INIT|STARTED|FAILED`; `LinkParameters{JsonString json}`.
Enums: `LinkStatus` = `LINK_UNDEF|CREATED|LOADED|DESTROYED`; `PackageStatus` = `PACKAGE_INVALID|SENT|RECEIVED|FAILED_GENERIC|FAILED_NETWORK_ERROR|FAILED_TIMEOUT`; `LinkType` = `LT_SEND|RECV|BIDI`.
`LinkProperties` has `supportedHints` (camelCase), `linkAddress`, `channelGid`, `worst/expected/best` (`LinkPropertyPair`), `mtu`, `duration_s`, `period_s`, …; `ChannelProperties` has `maxLinks`, `currentRole`, `creatorExpected`, `loaderExpected`, `supportedHints`, …

Header file names are flat in the plugin-builder image (`#include <ITransportSdk.h>`, not `<race/decomposed/ITransportSdk.h>`).

## 3. Canonical code patterns

File layout the template uses (names are replaced when you adapt it):

```
source/common/    log.{h,cpp}  JsonTypes.h  PersistentStorageHelpers.h
source/transport/ PluginStub.{h,cpp}   ITransportComponent + createTransport/destroyTransport
                  Link.{h,cpp}         one container + one worker thread
                  LinkAddress.{h,cpp}  the exchanged address (JSON)
                  LinkMap.{h,cpp}      thread-safe LinkID → Link
                  ServiceClient.h      the Phase-3 boundary (abstract)   StubClient.{h,cpp}  its HTTP implementation
config/           actions-send-only.json  actions.json  actions-combined.json
test/             adapter.py  run_scenarios.py  scenarios/*.json  source/ (gtest)
```

### 3.1 Parameters (`requestPluginUserInput`)

```cpp
PluginStub::PluginStub(ITransportSdk *sdk) : sdk(sdk), … {
    serverHandle = sdk->requestPluginUserInput("server", "Base URL of the service", false).handle;
    tokenHandle  = sdk->requestPluginUserInput("token",  "Access token for the service", true).handle;
}
ComponentStatus PluginStub::onUserInputReceived(RaceHandle handle, bool answered, const std::string &response) {
    if (handle == serverHandle) { serverHandle = NULL_RACE_HANDLE; … } else if (handle == tokenHandle) { … }
    else return COMPONENT_ERROR;
    if (both handles resolved) { all present ? sdk->updateState(COMPONENT_STATE_STARTED)
                                            : sdk->updateState(COMPONENT_STATE_FAILED); }
    return COMPONENT_OK;
}
```

- Answers arrive **asynchronously** after the constructor returns; the component is not usable until it calls `updateState(COMPONENT_STATE_STARTED)`. Stay in INIT until *every* answer is in; call `FAILED` if a required one is missing.
- The value comes from `race-cli --param <composition id>.<key>=<value>`. `<composition id>` is `compositions[].id` from the manifest. **Not** the library or `file_path` name — such a param is never delivered and the component waits/fails with no hint. The adapter must use the identical `<key>`.
- Secrets: the adapter passes `${ENV_VAR}` placeholders. `race-cli --debug` logs `Got parameter: '<key>' = '<value>'` — secrets appear in raw logs; treat `generated/` logs as secret (the template's `run_scenarios.py` masks the copies it preserves).

### 3.2 Link address

A plain struct with `to_json`/`from_json`, exchanged as a JSON **string** (`LinkProperties::linkAddress`, `--send-address`, `--recv-address`, `loadLinkAddress(…, const std::string&)`). Parse defensively, ignore unknown fields, reject a missing mandatory field and tell the SDK (`LINK_DESTROYED`). Keep secrets out.

### 3.3 Link lifecycle

```cpp
bool preLinkCreate(prefix, handle, linkId, LinkSide invalidRoleLinkSide) {
    if (links.contains(linkId)) { log; return false; }   // do NOT report LINK_DESTROYED: it would kill the live link
    if (!ready || links.size() >= maxLinks || currentRole.linkSide == LS_UNDEF || == invalidRoleLinkSide) {
        sdk->onLinkStatusChanged(handle, linkId, LINK_DESTROYED, {});   // always tell the SDK
        return false; }
    return true; }
```

| Call | Invalid role | Does | Reports |
|---|---|---|---|
| `createLink` | `LS_LOADER` | generate address, create container | `LINK_CREATED` |
| `createLinkFromAddress` | `LS_LOADER` | parse address, **reuse container if it exists** (non-owning) else create (owning) | `LINK_CREATED` |
| `loadLinkAddress` | `LS_CREATOR` | parse address; create nothing (container may not exist yet) | `LINK_LOADED` |
| `destroyLink` | — | delete container **only if creator and owning**; clear persisted cursor; join worker; remove | `LINK_DESTROYED` |

After success: `links.add(link); link->start(); sdk->onLinkStatusChanged(handle, linkId, status, {});`. Pass `{}` as params: the SDK reads the address from `getLinkProperties(linkId).linkAddress`, so `LinkProperties::linkAddress` must be set on every link (the template does it in the `Link` constructor). Return `COMPONENT_ERROR` on failure paths after reporting `LINK_DESTROYED`. `getLinkProperties` must never throw for an unknown id.

Default link properties are derived from the manifest's channel properties (`createDefaultLinkProperties` in `PluginStub.cpp`), so the manifest stays the single source of truth.

### 3.4 Actions

Action JSON (from the user model): `{"linkId": "<id>|*", "type": "post"|"fetch"|"cleanup"}`. `"*"` = every link.

```cpp
getTransportProperties(): { {"post",{"application/octet-stream"}}, {"fetch",{"application/octet-stream"}} }
getActionParams(action):  post  → {{linkId, kContentType, /*encodePackage*/ true,  "{}"}}
                          fetch → {{linkId, kContentType, /*encodePackage*/ false, "{}"}}
                          cleanup → {}            unknown → log + sdk->updateState(COMPONENT_STATE_FAILED)
```

- MIME types here are the **content contract with the encoding**: the framework picks the composition's encoding whose `getEncodingProperties().type` matches (patterns like `image/*` and `*/*` allowed). With several matching encodings it silently takes the first, so name the real type from the Phase 2 design.
- Return a parameter for `fetch` as well as `post`, carrying the (possibly `"*"`) link id: that is how the framework binds an action to links (`ComponentActionManager::createActionInfo`). The template does this; the older `decomposed-exemplars` returns `{}` for fetch.
- `enqueueContent(params, action, bytes)`: post only; empty content is a no-op; target link = `params.linkId` if concrete, else the action's (`"*"` → every **creator** link; queueing on loader links would just leak bytes). Store by `action.actionId`. Unknown link → `COMPONENT_ERROR`. `dequeueContent` erases it.
- `doAction(handles, action)`: **return immediately** — hand the request to the link's worker thread. `cleanup` → `COMPONENT_OK` (teardown is `destroyLink`). Unknown link → `COMPONENT_ERROR`; `"*"` with no links → `COMPONENT_OK`.

### 3.5 Link worker thread (`Link.cpp`)

`post(handles, actionId)` / `fetch(handles)` push a `QueuedAction` and notify a condition variable; `runActionThread` pops and runs `postOnActionThread` / `fetchOnActionThread`, mapping exceptions to package status:

- post success → `onPackageStatusChanged(h, PACKAGE_SENT)` for every handle + `onEvent`; transient service error → `PACKAGE_FAILED_NETWORK_ERROR`; anything else → `PACKAGE_FAILED_GENERIC`. A wildcard post reaches links that have no content: skip silently.
- fetch: only **loader** links fetch. For each new message in order: `sdk->onReceive(linkId, {linkId, kContentType, /*encodePackage*/ false, "{}"}, bytes)`, then advance **and persist** the cursor (`psh::saveValue`) — advance only after delivery so a failure retries the same message. A missing container is not an error (creator may be late).
- `std::mutex` + `condition_variable`; copy content under the lock; join the thread in `shutdown()`/destructor.

### 3.6 Events

`sdk->onEvent({json})` with e.g. `{"linkId":…, "actionId":…, "status":"posted"|"fetched"|"failed"}`; the user model may react. Document each emitted event in the Component Integration document.

### 3.7 Persistent storage

`psh::saveValue/readValue` (`PersistentStorageHelpers.h`) wrap `sdk->writeFile/readFile` — per-node, survives restarts. Use for fetch cursors. There is no delete; an empty value means absent.

### 3.8 Logging

`logDebug/logInfo/logWarning/logError` and `TRACE_METHOD(args…)` from `log.h` (backed by `RaceLog`). Never `fprintf(stderr…)`/debug files; never log secrets (token lengths included).

### 3.9 Pitfalls found while building the references

- `LinkMap::get` must return `nullptr` for unknown ids (the original `unordered_map::at` threw into the SDK thread).
- Range-`for` over a member of a temporary dangles: `for (auto &x : json::parse(s).at("ids"))` → silently empty. `auto j = json::parse(s); for (auto &x : j.at("ids"))`.
- `TRACE_METHOD`/gmock print their arguments with `operator<<`; a `std::vector<RaceHandle>` has none — leave it out.
- `createTransport` ignores `roleName`/`pluginConfig` in the references; `pluginConfig.pluginDirectory` is the kit directory (`/kits/<PluginName>/`) if you need to read shipped files.

## 4. Manifest (`source/manifest.json`)

Parsed by `raceboat/source/plugin-loading/Config.cpp` and `raceboat/source/common/ChannelProperties.cpp`. Keys not listed there are **silently ignored** (the log shows `Using default value for <key>` at DEBUG only).

```json
{
  "plugins": [{
    "file_path": "PluginStub",               // kit directory name under /kits and CMake PLUGIN_NAME
    "plugin_type": "comms", "file_type": "shared_library", "node_type": "any",
    "shared_library_path": "libPluginStub.so",   // exactly lib<CMake target>.so
    "channels": [], "transports": ["stub"], "usermodels": [], "encodings": []
  }],
  "channel_properties": {
    "stubComposition": {
      "channelGid": "stubComposition",        // == composition id == scenario slot value == --param prefix
      "bootstrap": false,
      "connectionType": "CT_INDIRECT",
      "linkDirection": "LD_CREATOR_TO_LOADER", // REQUIRED. also LD_LOADER_TO_CREATOR, LD_BIDI
      "transmissionType": "TT_MULTICAST",      // REQUIRED. TT_UNICAST | TT_MULTICAST (public container = multicast)
      "sendType": "ST_STORED_ASYNC",           // ST_STORED_ASYNC (service stores) | ST_EPHEM_SYNC
      "reliable": true, "isFlushable": false,
      "duration_s": -1, "period_s": -1, "mtu": -1,   // -1 = unlimited/unspecified
      "maxLinks": 10, "supportedHints": [],
      "maxCreatorsPerLoader": …, "maxLoadersPerCreator": …, "multiAddressable": …,   // optional
      "creatorExpected": {"send": {"bandwidth_bps": 1000000, "latency_ms": 10000, "loss": 0.0},
                          "receive": {…}},     // and loaderExpected; key names are EXACT
      "roles": [{"roleName": "default", "linkSide": "LS_BOTH"}]   // optional; default = one LS_BOTH role
    }
  },
  "compositions": [{
    "id": "stubComposition", "transport": "stub",
    "usermodel": "twoSixFileBasedUserModel", "encodings": ["noop"]   // may live in another plugin (see below)
  }]
}
```

(`//` comments are for this guide only; JSON has none.)

- Components named in a composition but implemented by **another** plugin (`twoSixFileBasedUserModel`, `noop` live in `decomposed-exemplars`) resolve automatically as long as both plugins are in `raceboat/test/integration/plugin_registry.json` and built; at runtime `race-cli --dir /kits` loads every kit it finds. A missing one fails with `needs component(s) […] but no plugin registered … provides them`.
- Wrong names to avoid (all seen in earlier syntheses): `bandwidth`/`latency` (must be `bandwidth_bps`/`latency_ms`), `supported_hints` (must be `supportedHints`), `creatorsPerLoader` (docs) vs `maxCreatorsPerLoader` (parser), a `shared_library_path` that is not the real `lib<target>.so` file name.
- `channel_parameters` (optional) lists parameters for UIs; `race-cli` does not need it.

## 5. Build system

The template's CMake is the standard raceboat layout, trimmed. Facts that matter:

- Build **only** inside the `raceboat-plugin-builder` image; it carries the race SDK headers/libs, `nlohmann_json`, `gtest/gmock`, curl, openssl, cpprest and boost under `/linux/<arch>`, selected by the preset's toolchain file. **Do not** use `FetchContent`/`ExternalProject` (needs network, builds libxml2 for nothing).
- `./build_artifacts_in_docker_image.sh` → `docker run … ./build_artifacts.sh` → `cmake --preset=LINUX_x86_64` + `cmake --build --preset …`. It honours `RACEBOAT_IMAGE_TAG` and never pulls over a local image.
- `source/CMakeLists.txt` defines `PLUGIN_NAME` and `setup_component_target(TARGET … SOURCES …)`: builds `lib<TARGET>.so` (hidden visibility, no SONAME), copies it **and** `manifest.json` **and** `config/*.json` into `kit/artifacts/<node>-{client,server}/<PLUGIN_NAME>/` after every build. The `.so` name, the manifest's `shared_library_path` and the adapter's `KIT_NAME` must agree.
- The library does not link `libraceSdkCommon`; its SDK symbols are resolved from `race-cli` at load time. Only unit-test binaries link it.
- A hand-rolled `cmake .. -DCMAKE_TOOLCHAIN_FILE=… -DNODE_TYPE=linux-x86_64` from the build script also works but is x86_64-only (hard-coded sysroot paths); prefer the template's presets.
- Unit tests: `-DBUILD_UNIT_TESTS=ON` (`./run_unit_tests.sh`). The binary links in the builder with `-Wl,--allow-shlib-undefined` and runs in the runtime image because the builder's `libraceSdkCommon.so` was built for a newer glibc.

## 6. Unit-test patterns

- Mock: `test/source/common/MockTransportSdk.h` (verbatim copy of `raceboat/test/common/MockTransportSdk.h`, with the flat include). Use `NiceMock<MockTransportSdk>`; give `getChannelProperties` (with `maxLinks` and a `currentRole`) and `getActivePersona` defaults. Return `ChannelResponse{CM_OK, handle}` from mocked SDK calls that need a handle (`requestPluginUserInput`).
- Fake service: `InMemoryServiceClient` (ordered ids, `NotFound` on post to a missing container). Inject through the second `PluginStub` constructor.
- Cover at least: address parse/round-trip/reject; `LinkMap` nullptr-on-miss; each link-creation call incl. wrong role, `maxLinks`, malformed address, duplicate id; owning vs non-owning destroy; `getActionParams` per type; enqueue → post → fetch → `onReceive` end to end; parameter flow to STARTED and to FAILED; post failure → package status.
- Link threads: wait on a `std::promise` filled from a mock action (5 s timeout), and `sleep_for(200ms)` only to prove *nothing* happens.
- Service client (Phase 3): test it separately from the component. The template's `StubClient` has no unit test; its first bug (the dangling range-`for`) was only caught by the integration run — add a test against a local fake server when adapting.

## 8. Phase checklist

1. **High-level design** — service suitability, addressing methods, content types, innocuousness ranking → `PHASE1_…md`.
2. **Precise design** — credentials, visibility, content types↔actions, direction, multicast/unicast, retention, safe deletion → `PHASE2_…md`; fixes `linkDirection`, `transmissionType`, MIME types.
3. **Service interaction** — `ServiceClient` implementation + tests + real round trip → `PHASE3_…md`.
4. **Transport component** — adapt the template; design doc (functionality, security, nuances); Component Integration doc; unit + 4 integration scenarios green.

### Component Integration document (required deliverable)

1. *User model interaction*: actions (`post`, `fetch`, `cleanup`), the content type each needs, valid `linkId` forms, events emitted (`posted`/`fetched`/`failed` with their JSON), the hints in `supportedHints`, timing constraints (service rate limits, minimum polling interval).
2. *Encoding interaction*: the MIME type(s) in `getTransportProperties`, size limits (`mtu`/service limits), required encoding parameters in `EncodingParameters::json`, and which provided encodings are suitable (`noop`, `base64`, …).
3. *Parameters*: every `<composition id>.<key>`, whether secret, default, example.
4. *Addresses*: the `LinkAddress` JSON schema with an example.

## 10. Debugging tips

- Component stuck in INIT → user-input handles never resolved (wrong `--param` prefix/key). Look for `Got parameter:` then `onUserInputReceived … answered=`.
- `LINK_DESTROYED` right after create → `preLinkCreate` rejected (role, `maxLinks`, not ready); the plugin logs the reason.
- `onReceive` never called → fetch lists nothing: address mismatch, cursor past the data, parse bug.
- Plugin not loaded → `shared_library_path`/`file_path` mismatch with the kit; run `generate_scenario.py --list-channels listener`.
- `race-cli` options: `raceboat/app/race-cli/main.cpp` (`--send-address`, `--recv-address`, `--param k=v`, `--num-packages`, `--timeout`, `--debug --logto FILE`).
